# Pivot Designs – context for Claude

Pivot Designs (Tim) makes decorative made-to-measure MDF cabinet doors and panels on a CNC router in a UK workshop, cut in VCarve Pro. It also sells on Etsy as PivotGB, but **the website must never mention or link to Etsy** (Etsy takes a large cut). This repo is the website pivotdesigns.co.uk: holding pages, a door configurator, and order requests that produce one DXF per order for VCarve.

The work is split into workstreams. **Read `docs/workstreams/README.md` first, then the brief for the workstream you've been asked to work on.** Before ending a session, update that brief (status, decisions, next tasks) so the next session can pick up without the chat history. Where everything lives (live site, Render, docs, artifacts) is in `docs/LINKS.md`.

## How the code fits together

- `server.js`: Express server that wires the parts together. It serves the static pages from `public/` and takes `POST /api/orders` from the configurator. Orders (and settings such as prices) are stored by `lib/store.js`: in Render Postgres when `DATABASE_URL` is set, otherwise in `data/orders.json` (wiped on every Render deploy).
- `lib/orders.js`: statuses, `createOrder` (validates every door again with the engine; used by customers and by Tim), and `mail()`, which notes each email in the order's history.
- `lib/admin.js`: the password-protected `/admin` pages (env `ADMIN_PASSWORD`): the order list with Action required flags and a Needs action queue, Confirm price, Mark paid, Mark dispatched, status, Archived view, Delete (paid orders need the reference typed), **email preview and edit before sending**, New order (`/configurator?admin` posts to `/admin/orders`, and nobody is emailed), DXF and JSON downloads, and a built-in "How this page works" guide.
- **Payment mode** (`lib/site.js`, switched on /admin/pricing, saved as the `mode` setting, live in **Quote first** until Tim switches): *Quote first* (`quote`, the original flow) or *Pay online* (`checkout`): customers pay straight away at the website price (`POST /api/orders` with `intent: "pay"` creates a `checkout: true` order already quoted, then `/pay/<ref>/checkout?t=` sends them to Stripe; no emails until paid; unpaid checkouts are archived after 7 days). Addresses outside the delivery area (`E.deliveryArea(postcode)`: Northern Ireland, Isle of Man, Channel Islands, Isles of Scilly, Isle of Wight, Scottish islands and Highlands) and anyone who clicks "Ask for a quote instead" send a quote request; the server refuses `intent: "pay"` for those postcodes too. **Pages carry wording for both modes** in `<!--mode:quote-->…<!--/mode-->` and `<!--mode:checkout-->…<!--/mode-->` blocks; server.js serves every page through `site.renderPage()`, which keeps the current mode's blocks and fills `__PIVOT_MODE__` (the configurator's `<body data-mode>`). Any new wording about how ordering works must come in both versions.
- **Email rule:** only customer actions send customer emails automatically (request received, paid by card). Anything Tim does sets `pendingEmail` on the order and opens a preview; nothing is sent until he presses Send.
- `lib/payments.js`: Stripe Checkout payment links (`/pay/<ref>?t=<token>`, prices valid 30 days) and the Stripe webhook (`checkout.session.completed`, `checkout.session.async_payment_succeeded`, and `charge.refunded` for automatic refund tracking). Env `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `SITE_URL`. Test everything with `npm test` (`scripts/test.js`).
- `lib/email.js`: emails through Resend (env `RESEND_API_KEY`, optional `EMAIL_FROM`, `EMAIL_ADMIN`). The automatic ones are new order (to Tim and the customer) and paid by card (to the customer and Tim). Editable drafts (`KINDS`: paylink, paid, dispatched, refunded, custom) are sent from the admin preview. A failed email never blocks an order.
- `public/js/engine.js`: **the single source of truth for doors.** It works in the browser (`window.PivotEngine`) and in Node. It holds the design recipes, size limits, prices (bands, set from /admin/pricing), SVG preview and R12 DXF writer. The configurator, the server and the scripts all use it, so a recipe change shows up everywhere.
- `public/configurator.html` + `public/js/configurator.js` + `public/css/configurator.css`: the customer configurator. `?test` in the URL shows a Download test DXF button; `?admin` is Tim creating an order. The address uses separate fields (line 1, line 2, town, postcode, with the postcode checked as UK) and an optional search box.
- `lib/address.js`: UK address search through Ideal Postcodes, proxied by the server so the key (env `IDEAL_POSTCODES_KEY`) stays private, with limits per visitor. Suggestions are free; each address picked costs a lookup. Without the key the search box is hidden. The API field names (`hits[].id/suggestion`, `line_1..3`, `post_town`, `postcode`) come from memory, because the docs were blocked here; check them on the live site.
- Pictures for each design: `public/data/design-images.json` + `public/img/designs/` (AI renders need `"illustration": true`).
- `public/index.html`, `story.html`, `contact.html`, `404.html` + `public/css/site.css`: site pages. The header and footer are repeated in each page, so change all of them.
- `scripts/sample-dxf.js`: writes one full-size test DXF per design plus one combined file.
- `scripts/test-board-dxf.js`: writes one 1220 x 500 mm offcut board with the draft designs, hand-placed, with full-size details.
- Hosting: Render web service `pivot-site` (Starter plan) deploys automatically from `main` within about a minute. Domain DNS is at 123-reg: the A record for `@` points to 216.24.57.1, and `www` is a CNAME to `pivot-site.onrender.com`. **Never touch the MX, SPF, DKIM, DMARC or autodiscover records;** they carry Tim's email. Resend's records (`resend._domainkey`, `rsend`, `send`) were added on 20 Nov 2026 for order emails.

## Decisions that hold everywhere

- Doors are 18 mm MDF only. Sizes are in mm. Customer limits are 300–1000 mm wide and 300–1200 mm tall (the machine takes 1200 × 1200 sheets; 1000 × 1200 is the largest that can be held down safely).
- Hinge holes are an optional service (default: none): 35 mm cups, 22.5 mm from the edge. The customer sets the side, count (2 to 4), the top and bottom distances (default 100 mm, minimum 50) and optional hinge notes. All of this goes on the DXF LABELS layer only, with no back-side machining. The site doesn't say how they're drilled.
- Designs can be **archived** (`archived: true` in engine.js): hidden from the configurator and refused for new orders, but kept so old orders can still produce a DXF. Archived since 20 Nov 2026: Fluted shaker, Moulded frame fluted, Victorian, Arch-top beaded door, Ring and arc panel; Diamond lattice since 24 Nov 2026. Site copy must never state how many designs there are.
- The bevelled shaker is a flat frame, then a 45 degree bevel (90 degree V-bit, 8 mm wide to match the depth) down to a flat panel pocketed 8 mm deep. Layers: `BEVEL_D8` (the top edge of the bevel) and `POCKET_D8` (the panel floor). Older orders keep 5 mm (version 4) or 5 mm with a 12 mm bevel (`BEVEL_W`, before version 4).
- One DXF per order, in mm, with parts spread apart for VCarve to nest. Each cut has its own layer named by the type of cut and its depth only, with no tool names (e.g. `POCKET_D8`, `VGROOVE_D4`, `BEVEL_D8`, `ROUNDOVER`); Tim picks bits and toolpaths in VCarve (decided 24 Nov 2026). Plus `CUTOUT` (outline), `LABELS`, and grooves overcut 10 mm past the edge where they run off the door.
- **Depths and widths in `TOOLS` (top of engine.js) are placeholders** until Tim's test cuts confirm them.
- Shaker pockets: Traditional 8 mm deep, frame 40–120 mm; Skinny 5 mm deep (so hinge cups don't weaken the face), frame 18–35 mm. Arched doors can be single, left, right or a pair (one line, two doors, default 3 mm gap).
- Every pocket shows customers its depth and a 1.5 mm inside-corner radius (1/8 in downcut or 2 mm finishing bit). The bevel (90 degree V-bit) is as wide as the pocket is deep. Beaded shaker = 12.7 mm round-over moulding rail on the pocket edge. Reeds are fixed at 12.5 mm. Board patterns can be "Fit evenly" or "Exact width". Options are ordered frame width, then pattern sliders, then toggles; every slider has a linked number box. Arched doors are mirrored about the door or pair centre line, sized by a side margin.
- Designs with `lab: true` appear only on the unlinked test page `/test-designs` and can't be ordered.
- Customer rules: complex or statement designs are size only; shaker types can adjust borders and rails; flutes, reeds and grooves can adjust spacing but not groove size (set by the bit).
- Order requests save a door spec (design, version, sizes, options), and the DXF is made from the spec, so it can be made again.
- **Prices (live 24 Nov 2026): Tim's Etsy band prices less 10%, rounded down, same for every design**, so website customers always pay less than on Etsy. Bands: Small up to 300 × 600 (Etsy £30 → £27), Regular up to 600 × 600 (£40 → £36), Large up to 600 × 1150 (£60 → £54), Extra large up to 800 × 1150 (£75 → £67). Bigger doors: Extra large price × the door's share of a usable half sheet ÷ the 800 × 1150 share (1220 sheet, 30 mm border, 25 mm gap, half of any wasted strip), at least £67; 1000 × 1200 = £90. Delivery £12 + £5 each extra (same as Etsy), free from £400. Tim edits the Etsy prices, discount, delivery and sheet settings on **/admin/pricing**: Etsy figures and the discount are saved privately (`pricingRef` setting); only the website prices go in the `pricing` setting and on `/api/pricing`. **Never put "Etsy" in anything public**, including `/api/pricing`. The earlier sheet-share formula with design factors (6 × £21 per half sheet, £12 per door, factors 1–1.55) is recorded in docs/workstreams/business.md for later machining-time pricing.
- The trade portal (white-label quoting for fitters) is planned for later. See the Trade Portal Plan.

## Working style

- Tim isn't a developer. Explain steps in plain words, give exact clicks for Render, 123-reg and GitHub, and confirm before anything that changes DNS, deletes data, or costs money.
- Test DXF changes by reading the file back (e.g. with the Python `ezdxf` package) and by drawing it, before saying they work.
- Commit to `main` only when asked or when finishing agreed work. Render deploys `main` straight to the live site.
- Don't present AI-generated images as real photos on the site. Label them as illustrations.
